🌳 Git Branch Stratejisi - Multi-Tenant SaaS

Spormanage için müşteriye özel özelleştirme stratejisi

📌 Amaç:
✅ Tek repository'de birden fazla müşteri yönetimi
✅ Local development ile production izolasyonu
✅ Müşteriye özel özelleştirmeleri destekleme
✅ Kod tekrarını minimize etme

1️⃣ Branch Yapısı

main (production base - tüm müşteriler için ortak kod) │ ├── dev (local development) │ ├── customer/ozluce (Özlüce'ye özel) │ ├── customer/kultur (Kültür'e özel) │ └── customer/gspay (GS Pay'e özel)

Branch Açıklamaları:

Branch Amaç Kullanım Coolify Bağlantısı
main Ana production branch Tüm müşterilere ortak özellikler Varsayılan
dev Local geliştirme Yeni özellikler test edilir -
customer/ozluce Özlüce özelleştirmeleri Sadece Özlüce'ye özel kod ✅ Özlüce App
customer/kultur Kültür özelleştirmeleri Sadece Kültür'e özel kod ✅ Kültür App
customer/gspay GS Pay özelleştirmeleri Sadece GS Pay'e özel kod ✅ GS Pay App

2️⃣ Workflow Senaryoları

📦 Senaryo 1: Ortak Özellik Geliştirme (Tüm Müşteriler)

Örnek: Tüm müşterilere yeni bir rapor özelliği eklemek istiyorsun.

Adım 1: dev branch'te geliştir 
git checkout dev
git pull origin main

# Yeni özelliği geliştir
# ...kod yaz, test et...

git add .
git commit -m "feat: yeni rapor özelliği eklendi"
Adım 2: main'e merge et 
git checkout main
git merge dev
git push origin main
Adım 3: Tüm müşteri branch'lerini güncelle 
git checkout customer/ozluce
git merge main
git push origin customer/ozluce

git checkout customer/kultur
git merge main
git push origin customer/kultur

git checkout customer/gspay
git merge main
git push origin customer/gspay
✅ Sonuç: Tüm müşteriler yeni rapor özelliğini aldı. Coolify otomatik deploy yapacak.
🎯 Senaryo 2: Özlüce'ye Özel Özellik

Örnek: Özlüce sadece kendi okulu için özel bir ödeme planı istiyor.

Adım 1: Özlüce branch'ine geç 
git checkout customer/ozluce
Adım 2: Özel özelliği geliştir 
# Özlüce'ye özel kod yaz
# src/app/api/payments/ozluce-special/route.ts oluştur

git add .
git commit -m "feat(ozluce): özel ödeme planı eklendi"
git push origin customer/ozluce
✅ Sonuç: Sadece Özlüce bu özelliği aldı. Diğer müşteriler etkilenmedi.
🔄 Senaryo 3: Özel Özelliği Tüm Müşterilere Yaymak

Örnek: Özlüce için geliştirilen özellik çok başarılı oldu, diğer müşteriler de istiyor.

Adım 1: Özlüce'deki commit'i al 
git checkout main
git log customer/ozluce  # Commit hash'i bul

git cherry-pick 
git push origin main
Adım 2: Diğer müşterilere merge et 
git checkout customer/kultur
git merge main
git push origin customer/kultur

git checkout customer/gspay
git merge main
git push origin customer/gspay
✅ Sonuç: Özel özellik artık tüm müşterilerde var.

4️⃣ Alternatif: Feature Flags (Önerilen)

💡 Neden Feature Flags?
• Tek codebase, kolay bakım
• Git conflict'leri yok
• Environment variable ile kontrol
• Deploy süreci basit

Örnek Implementasyon:

1. Customer Config Oluştur: 
// src/config/customer.ts
export const getCustomerConfig = () => {
  const customerId = process.env.CUSTOMER_ID || 'default'
  
  const configs = {
    ozluce: {
      name: 'Özlüce Futbol Okulu',
      features: {
        customReport: true,
        specialPayment: false,
        advancedStats: true,
      },
      theme: {
        primaryColor: '#10b981',
        logo: '/logos/ozluce.png',
      },
    },
    kultur: {
      name: 'Kültür Futbol Okulu',
      features: {
        customReport: false,
        specialPayment: true,
        advancedStats: false,
      },
      theme: {
        primaryColor: '#f59e0b',
        logo: '/logos/kultur.png',
      },
    },
    gspay: {
      name: 'GS Pay Futbol Okulu',
      features: {
        customReport: false,
        specialPayment: false,
        advancedStats: true,
      },
      theme: {
        primaryColor: '#ef4444',
        logo: '/logos/gspay.png',
      },
    },
  }
  
  return configs[customerId] || configs.default
}
2. Kullanım: 
// src/app/reports/page.tsx
import { getCustomerConfig } from '@/config/customer'

  return (

}

5️⃣ Karşılaştırma: Branch vs Feature Flags

🌳 Customer Branches

Avantajları:

  • Tam kod izolasyonu
  • Müşteri-specific kod açıkça ayrı
  • Bağımsız deployment

Dezavantajları:

  • Git merge conflict'leri
  • Branch yönetimi zor
  • Kod tekrarı artabilir
  • Her müşteri için sync gerekli

🚩 Feature Flags

Avantajları:

  • Tek codebase, kolay bakım
  • Merge conflict yok
  • Environment variable ile kontrol
  • A/B testing mümkün

Dezavantajları:

  • Kod içinde if-else çoğalır
  • Test karmaşıklaşabilir
  • Eski feature flag'ler temizlenmeli

6️⃣ Öneri: Hibrit Yaklaşım

✅ En İyi Strateji:

  1. Küçük özelleştirmeler için: Feature Flags kullan
  2. Büyük, kompleks özelleştirmeler için: Customer Branch kullan
  3. Ortak özellikler: main branch'te tut

Karar Ağacı:

Soru 1: Bu özellik tüm müşterilere mi gerekli?
  • ✅ Evet → main branch'e ekle
  • ❌ Hayır → Soru 2'ye geç
Soru 2: Özelleştirme basit mi (UI rengi, logo, küçük toggle)?
  • ✅ Evet → Feature Flag kullan
  • ❌ Hayır (kompleks iş mantığı) → Customer Branch kullan

7️⃣ Düzenli Bakım Komutları

Haftalık Sync (main → customer branches):

#!/bin/bash
# sync-customers.sh

echo "Syncing main to customer branches..."

git checkout main
git pull origin main

for branch in customer/ozluce customer/kultur customer/gspay; do
  echo "Syncing $branch..."
  git checkout $branch
  git merge main
  git push origin $branch
done

git checkout main
echo "✅ All customer branches synced!"

Branch Temizliği:

# Eski feature branch'lerini temizle
git branch -d feature/old-feature

# Remote'ta olmayan local branch'leri sil
git fetch --prune

# Merge edilmiş branch'leri listele
git branch --merged main

8️⃣ Best Practices

⚠️ Yapma Bunları:
  • ❌ Müşteri branch'lerinde doğrudan geliştirme yapma
  • ❌ main branch'e müşteriye özel kod merge etme
  • ❌ Aynı dosyayı farklı customer branch'lerinde değiştirme
  • ❌ Merge conflict'leri görmezden gelme
✅ Yap Bunları:
  • ✅ Önce dev branch'te test et
  • ✅ Düzenli olarak main'i customer branch'lerine merge et
  • ✅ Feature flag'leri dokümante et
  • ✅ Commit mesajlarına müşteri adı ekle: feat(ozluce): ...
  • ✅ Pull request'ler ile code review yap

9️⃣ Örnek Commit Mesajları

# Ortak özellik
feat: yeni rapor modülü eklendi

# Müşteriye özel
feat(ozluce): özel ödeme planı eklendi
fix(kultur): logo görüntüleme sorunu düzeltildi

# Feature flag ile
feat: özel rapor özelliği eklendi (feature flag: ENABLE_CUSTOM_REPORT)
